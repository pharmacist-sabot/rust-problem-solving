## PS 01: การเป็นเจ้าของของ self ในฟังก์ชันเมมเบอร์

ในบทนี้เราจะพิจารณาคำถามพื้นฐานเกี่ยวกับความหมายของการประกาศเมทอด (method) ที่รับ `self` ว่า:

> “การรับ `self` ในเมทอด หมายความว่าฟังก์ชันจะ **เป็นเจ้าของ (take ownership)** ของค่าที่เราส่งเข้าไปจริงหรือไม่?”

คำถามนี้สำคัญต่อการออกแบบ API และการจัดการทรัพยากรใน Rust เพราะการเป็นเจ้าของค่าหมายถึงค่าถูกย้าย (moved) เข้าไปในฟังก์ชันและไม่สามารถนำกลับมาใช้จากจุดเรียกเดิมได้ :contentReference[oaicite:1]{index=1}

## ตัวอย่างปัญหา

สมมติว่ามีโค้ดฟังก์ชันจากมาตรฐานไลบรารี:

```rust
pub fn cos(self) -> f32
```

เมื่อเรียกเมทอดนี้:

```rust
let angle = 0.0f32;
let cosine = angle.cos();
println!("angle = {angle}, cosine = {cosine}");
```

โค้ดนี้คอมไพล์และทำงานได้โดยไม่มี error แม้ว่าฟังก์ชันจะรับ `self`

จุดที่ทำให้เกิดข้อสงสัยคือ

> “ถ้า `cos(self)` รับ `self` โดยค่าที่จะย้าย ownership แล้วทำไม `angle` ยังถูกใช้งานใน println! โดยไม่มี error?”

คำตอบของคำถามนี้และแนวคิดที่เกี่ยวข้องคือหัวใจของบทนี้

## การวิเคราะห์ความหมายของ `self`

ใน Rust ทุกฟังก์ชันหรือเมทอดมีชนิด (signature) ที่ชัดเจนว่าพารามิเตอร์ใด _take ownership_, _borrow immutable_, หรือ _borrow mutable_ จากค่าที่ส่งเข้าไป

### 1. เมื่อเมทอดประกาศรับ `self`

```rust
impl SomeType {
    fn consume(self) -> ReturnType { ... }
}
```

นี่หมายความว่าเมทอดจะ **ย้าย ownership ของค่าที่เรียกใช้เมทอดเข้าไปในฟังก์ชัน** — นั่นคือค่าเดิมจากจุดเรียกจะถูก _moved_ เข้าไปในเมทอด และค่าเดิมจะไม่สามารถใช้งานอีกต่อไปหลังจากเรียกเมทอด

### 2. ความแตกต่างระหว่าง `self`, `&self`, และ `&mut self`

Rust มีสามรูปแบบการรับค่า `self` ในเมทอด:

- `self` — ส่งค่าทาง ownership โดยตรง (move)
- `&self` — ส่งค่าทาง borrow แบบแชร์ (immutable borrow)
- `&mut self` — ส่งค่าทาง borrow แบบ exclusive (mutable borrow)

เมื่อเมทอดประกาศรับ `self` ทาง Rust จะย้ายค่าเข้าสู่ฟังก์ชันในแบบ _ownership transfer_ อย่างไรก็ตามผลลัพธ์นี้อาจไม่ปรากฏเหมือน “ค่าหายไป” หากค่าที่ถูกย้ายเป็นชนิดที่ implements trait `Copy` — ในกรณีนี้การย้ายค่าในทางปฏิบัติจะเป็น _bitwise copy_ แทนการย้ายแบบจริงจัง และตัวแปรเดิมยังคงใช้งานได้เหมือนเดิมหลังจากเรียกเมทอด

## ทำไม `angle.cos()` ถึงไม่ทำให้ `angle` หายไป

ชนิดข้อมูลพื้นฐานของ Rust เช่น `f32`, `i32` หรือ `bool` หลายชนิด implement trait `Copy`

เมื่อชนิดข้อมูล implement `Copy`:

- การส่งค่าทางพารามิเตอร์โดยตรง (`self`, หรือผ่านฟังก์ชัน) จะ **ไม่ย้าย ownership จริง** แต่จะทำการคัดลอกค่าทางบิต (bitwise copy)
- ดังนั้น `angle.cos()` จะทำให้ค่า `angle` ถูก _copy_ เข้าไปในเมทอดแทนที่จะถูกย้ายจริง และเรายังสามารถใช้งาน `angle` ต่อไปหลังจากเรียกเมทอดได้

สรุป: ในกรณีนี้เมทอดรับ `self` แต่ค่าที่ถูกส่งเข้าฟังก์ชันเป็นชนิดที่ implement `Copy` จึงไม่ถูก “ย้ายจริง” และจึงไม่เกิด error “use of moved value”

## ทำไมจึงใช้ `self` แทน `&self` ในกรณีนี้

เมื่อชนิดข้อมูลเป็นชนิดเล็ก เช่น `f32` หรือ `i32`:

- การรับ `self` และ `&self` มีผลลัพธ์ทาง performance ใกล้เคียงกัน
- Rust ไม่มีความต่างเชิงประสิทธิภาพในการ dereference
- การรับ `self` ทำให้ API อ่านง่ายกว่าเมทอดที่ไม่ต้องอ้างอิง (`&`) เสมอ

ด้วยเหตุนี้ฟังก์ชันเช่น `f32::cos` มักประกาศด้วย `fn cos(self) -> f32` แทน `fn cos(&self) -> f32` เพื่อให้สอดคล้องกับนิยาม “ฟังก์ชันที่รับค่าทาง value โดยตรง” มากกว่า reference

## การใช้ `self` กับชนิดที่ไม่ implement `Copy`

เมื่อชนิดข้อมูลไม่ implement trait `Copy` เช่น `String`, `Vec<T>`, หรือ struct ที่ประกอบด้วยชนิดเหล่านี้:

- การประกาศเมทอดรับ `self` จะ **ย้าย ownership ของค่าลงในเมทอด**
- หลังจากเรียกเมทอดแล้ว ตัวแปรเดิมจะ **ไม่สามารถใช้งานได้อีก** ถ้าค่าถูกย้ายอย่างจริงจัง

ตัวอย่าง:

```rust
struct MyStruct(String);

impl MyStruct {
    fn into_inner(self) -> String {
        self.0
    }
}

fn main() {
    let s = MyStruct(String::from("hello"));
    let inner = s.into_inner(); // ownership ของ s ย้ายเข้าเมทอด
    // `s` ห้ามใช้งานต่อ
}
```

ในกรณีนี้ `into_inner(self)` เหมาะกับการรับ `self` เพราะเมทอดต้องการบริโภคค่าทั้งหมดเพื่อดึงค่าข้างในออกมา

## สรุป

การประกาศเมทอดใน Rust ว่า `fn foo(self)` มีความหมายดังนี้:

- โดยทั่วไปหมายถึงเมทอดจะ **take ownership** ของค่าที่เรียกใช้
- ถ้าชนิดที่เรียกใช้เป็นชนิดที่ implement trait `Copy` การย้าย ownership นี้จะถูกแปลงเป็น _copy_ แทน ทำให้ตัวแปรเดิมยังใช้งานได้หลังเรียกเมทอด
- การเลือกใช้ `self`, `&self`, หรือ `&mut self` ขึ้นอยู่กับว่าฟังก์ชันต้องการย้าย ownership, ยืมแบบ immutable หรือยืมแบบ mutable ตามการออกแบบ API

รูปแบบที่ถูกต้องเพื่อแยกความหมายคือ:

```text
self        -> ownership transfer (move)
&self       -> immutable borrow
&mut self   -> mutable borrow
```

เมื่อเข้าใจความหมายนี้แล้ว เราสามารถอ่าน signature ของเมทอดใน Rust แล้วรู้ได้ทันทีว่าฟังก์ชันนั้นจะ mengambil (ย้าย) ownership หรือเพียงแค่ borrow ค่าเดิมหรือไม่
